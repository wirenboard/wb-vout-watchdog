# wb-vout-watchdog

Сервис-сторож питания Vout для контроллеров Wiren Board. Следит за входным
напряжением (Vin) и управляет коммутируемой клеммой Vout: при просадке Vin ниже
настроенного порога обесточивает Vout и блокирует повторное включение до
явного разрешения извне.

## Как это работает

**Три зоны по напряжению.** Сервис периодически измеряет Vin и сравнивает его с
двумя порогами:

- **Норма** — Vin на уровне порога аварии или выше: сервис не вмешивается.
- **Просадка** — Vin между порогом включения резервного питания и порогом
  аварии. Если Vin держится в этой зоне дольше минимальной длительности
  просадки, сервис поднимает флаг `undervoltage` и выключает Vout.
- **Резервное питание** — Vin ниже порога включения резервного питания (по
  умолчанию 11 В — при этом напряжении автоматически включается модуль
  WBMZ-BATTERY). Здесь Vout питается от аккумулятора, поэтому сервис её не
  трогает и флаг не поднимает. Отсчёт минимальной длительности просадки при
  этом обнуляется — засчитывается только непрерывная просадка.

**Флаг аварии требует ручного сброса.** Однажды поднятый `undervoltage` сам не снимается —
как бы дальше ни вело себя Vin (восстановление входного напряжения само по себе
ничего не меняет). Снять флаг может только внешняя система — записью `1` в
контрол `enable_vout` по MQTT. Флаг переживает перезапуск сервиса и перезагрузку
контроллера.

**Двухшаговое включение.** Запись `1` в контрол `enable_vout` только
разблокирует: снимает флаг и возвращает управление Vout. Сам Vout при этом
остаётся выключенным — включить его нужно отдельной записью `1` в контрол
`V_OUT`. Так возврат питания не происходит автоматически. Если к моменту
разблокировки Vin всё ещё в зоне просадки, авария срабатывает повторно — после
каждой аварии нужна новая запись в `enable_vout`.

**Старт и рестарт.** При запуске сервис монопольно захватывает линию Vout. Флаг
`undervoltage` и состояние Vout восстанавливаются из персистентных файлов. При
снятом флаге Vout возвращается в то состояние, что было до остановки (так же
восстанавливает свои выходы wb-mqtt-gpio). При поднятом флаге Vout принудительно
выключается и остаётся заблокированным до разрешения. Накопленное время просадки
при старте не восстанавливается — отсчёт начинается заново.

**Поведение при сбоях.** Просадку сервис определяет сам, по прямому чтению АЦП,
независимо от MQTT. Потеря связи с брокером Vout не трогает: MQTT отвечает только
за разрешение обратного включения, а не за обнаружение просадки. Серия подряд
идущих ошибок чтения АЦП (по умолчанию 3) трактуется как авария — Vout
выключается. После восстановления связи сервис заново подписывается на топики
записи в контролы и переопубликовывает состояние всех контролов.

**Монопольность и наблюдаемость.** Пока сервис жив, линию Vout держит только он —
прямое управление другими процессами отклоняет ядро. Состояние видно в homeui
как обычное MQTT-устройство. Vin читается напрямую из sysfs IIO, поэтому
wb-mqtt-adc продолжает работать штатно.

Канал АЦП для Vin и линию GPIO для Vout в конфиге задавать не нужно — сервис
определяет их сам по device tree контроллера.

## MQTT-устройство `/devices/wb-vout-watchdog`

Внешняя система взаимодействует с сервисом записью в топики `.../on` его
контролов, как принято в WB. Собственных RPC-команд у сервиса нет.

- `controls/undervoltage` — alarm, read-only, retained. `1` — обнаружена
  просадка Vin ниже порога, Vout из-за этого выключен и заблокирован, нужно
  разрешение. Флаг требует ручного сброса: восстановление Vin его не снимает,
  он переживает рестарт сервиса и перезагрузку контроллера. Сбрасывается только
  записью `1` в контрол `enable_vout`.
- `controls/V_OUT` — switch, retained. Значение — фактическое состояние линии
  Vout, запись — в топик `.../V_OUT/on`. Пока поднят `undervoltage`, контрол
  становится read-only (meta переопубликовывается с `readonly=true`, homeui
  прячет переключатель) и записи игнорируются. После снятия флага снова
  writable.
- `controls/enable_vout` — pushbutton. Запись `1` в `.../enable_vout/on` —
  разрешение от внешней системы: снимает флаг `undervoltage` и возвращает
  `V_OUT` writable. Сам Vout при этом НЕ включается — включение отдельной
  записью `1` в `V_OUT`. Если просадка продолжается, авария сработает повторно.
  При снятом флаге запись ничего не делает.
- `controls/heartbeat` — unix timestamp, retained. Признак жизни сервиса:
  обновляется раз в период (рекомендуемый критерий смерти — 3 пропущенных
  периода).
- `controls/vin` — value (В), read-only, retained. Текущее измеренное Vin, для
  диагностики. На каждый неудачный опрос АЦП у контрола выставляется
  `meta/error=r`, снимается первым успешным чтением.

## Сосуществование с wb-mqtt-gpio

Сервис монопольно захватывает линию V_OUT на всё время работы — управлять ей из
других процессов ядро не даёт. wb-mqtt-gpio при этом не
переконфигурируется: его канал `V_OUT` постоянно висит с `meta/error=r`, и это
ожидаемое состояние, а не проблема.

Проверить, кто держит линию, можно штатным `gpioinfo` — занятая нами линия
показывается как `used` с меткой потребителя `wb-vout-watchdog`.

## Конфигурация

`/etc/wb-vout-watchdog.conf` — JSON, редактируется через homeui (confed) или
вручную. Ключи со значениями по умолчанию:

```jsonc
{
    // Порог аварии, В. Просадка Vin ниже него дольше min_low_voltage_duration_s
    // поднимает флаг undervoltage и выключает Vout.
    "alarm_threshold_v": 20.0,

    // Минимальная длительность просадки, с. Сколько Vin должен непрерывно
    // держаться ниже alarm_threshold_v, чтобы это считалось аварией.
    "min_low_voltage_duration_s": 5.0,

    // Порог включения резервного питания, В (по умолчанию — порог автовключения
    // WBMZ-BATTERY). Ниже него Vout питается от аккумулятора и сервис не
    // вмешивается. Должен быть 0 или меньше alarm_threshold_v.
    "battery_backup_threshold_v": 11.0,

    // Период опроса АЦП, с.
    "adc_poll_period_s": 1.0,

    // Сколько подряд идущих ошибок чтения АЦП трактуется как авария.
    "adc_error_threshold": 3,

    // Период публикации heartbeat, с.
    "heartbeat_period_s": 10.0
}
```
